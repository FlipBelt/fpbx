# 管理员代发案件（admin-originator-v1）

## 目的

员工已经把报销资料交给管理员、但员工端无法完成提交时，管理员可以在“系统管理 → 排障案件 → 新建管理员代发”建立受控案件。案件保存后仍需管理员复核，并点击“管理员代发起”才会创建钉钉 OA。

## 身份规则

- 不读取、借用员工个人 Token。
- 管理员身份只用于权限校验、操作审计和处理原因。
- OA 的 `originatorUserId` 使用案件归属员工的钉钉 `userId`。
- OA 部门和社保付款公司在服务端重新读取员工档案；浏览器粘贴的身份字段不会覆盖服务端结果。
- 普通自报和普通“代他人报销”入口继续使用原有路由，不会进入此分支。

## 管理台开关

`REIMBURSEMENT_ADMIN_MANUAL_CREATE_ENABLED=true` 只开放“新建管理员代发”能力；它仍受现有定时发送管理员名单、工作台数据库、`repair` 和 `submit` 独立开关共同限制。

## 操作步骤

1. 管理员从钉钉重新打开应用，进入“系统管理”。
2. 在案件页点击“新建管理员代发”，搜索归属员工并确认其 `userId`。
3. 粘贴员工已确认的完整报销草稿 JSON，填写业务原因并保存案件。
4. 打开案件，使用“高级代修复”补齐或修正表单、明细、附件绑定和付款公司。
5. 复核案件版本、社保主体、部门和凭证校验结果，再点击“管理员代发起”。
6. 以返回的 OA 实例号在钉钉核对发起人确为归属员工；失败或不确定时不要重复点击，先查看案件时间线和幂等记录。

## 接口

- `GET /api/admin/workbench/employees?session_token=...&q=...`：仅管理员可用的员工检索。
- `POST /api/admin/workbench/manual-cases`：创建加密案件；不会发起 OA。
- `POST /api/admin/workbench/cases/:id/repair`：同一后端校验链路下保存修复版本。
- `POST /api/admin/workbench/cases/:id/submit`：通过完整校验后，以员工为 OA 发起人创建审批。

案件草稿、社保识别结果和附件归档继续遵守既有加密与 60 天保留策略；管理员操作写入 `admin_actions` 并使用幂等键防止重复创建 OA。
