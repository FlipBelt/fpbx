# 月度报销定时发起模块

## 当前状态

- 功能由生产功能开关控制；启用后会使用真实钉钉审批链路。
- 功能开关开启后，普通用户报销只按提交日期决定去向，不按金额、入口或旧的紧急标记分流。
- 每月 1 日至 20 日提交：进入当月待发起池，21 日 09:00 开始释放；21 日至 25 日提交：直接发起 OA；26 日至月底提交：进入下月待发起池。
- 时间均按 Asia/Shanghai 计算。待发起池只在每天 09:00—18:00 工作时间内释放，按提交顺序每 3 分钟最多释放 1 笔；实际时槽会写入每笔记录，供用户和管理员查看。18:00 后暂停，次日 09:00 继续，不会在午夜或非工作时间自动发起。

## 用户看到的结果

用户点提交后，系统会先完成与即时发起相同的必填、业务关联、OCR 和金额校验，然后保存不可变提交快照。保存成功后页面显示“报销提交成功”，并以小字说明预计自动发起 OA 的时间。用户不需要理解“队列”或“待发起池”。

在尚未真正发起 OA 前，用户可以在提交记录中“撤销并复制为草稿”。系统撤销原记录后恢复可编辑草稿，不会修改已锁定的原始快照。

## 发起人身份

快照保存提交当时由钉钉登录态核验过的 `originator_user_id`、部门和完整 OA 表单数据。定时执行时使用企业内部应用凭证调用钉钉，但 OA 发起人仍取快照中的真实提交人，不依赖数天后已经过期的浏览器会话。

## 数据与附件

- SQLite 文件：`data/scheduled-approvals.sqlite`，使用 WAL、FULL synchronous 和原子事务。
- 完整表单、发起人和附件标识使用 AES-256-GCM 加密保存；数据库文件权限设为仅服务账号可读写。
- 用户列表和管理列表只返回脱敏摘要，完整快照仅在发送工作进程领取任务或用户撤销恢复草稿时解密。
- 附件使用上传后由钉钉返回的空间 ID、文件 ID 和文件元数据，不依赖浏览器临时文件。本地测试已验证这些字段经过加密落库、关闭数据库并重新打开后无丢失。
- 上线前仍需在测试 OA 模板中做一次跨天附件有效性验收；这项只能由真实钉钉环境验证，不能用本地模拟替代。

## 防重复与故障处理

1. 同一用户、同一提交编号在数据库中有唯一约束；重复点击只返回原结果。
2. 工作进程用事务领取任务和租约，同一任务不能被两个进程同时领取。
3. 明确的临时错误按退避策略自动重试；明确的业务错误转人工处理。
4. 超时、连接中断或工作进程在发送中重启时，结果进入“待核对”，绝不盲目重发。
5. 若 OA 模板配置了“定时发送追踪号”文本组件，系统会写入唯一追踪号，并在待核对状态下查询发起人的近期 OA。查到匹配实例即恢复为成功，不再重发。
6. 查不到时继续保持待核对。管理员必须先在 OA 核实，再点“确认 OA 未创建后重发”。

若 OA 模板尚未增加追踪号组件，应将 `trackingComponentName` 留空。系统仍安全运行，但未知结果只能人工核对，不能自动对账。

## 并发与性能

- 定时池始终单并发；一个调度轮次最多发起 1 笔 OA。
- 默认每 3 分钟检查并释放下一笔，不能因配置或重启形成批量突发。
- Web 服务与定时发送工作进程分离。页面访问、OCR 上传与批量发送互不抢占同一个 Node 事件循环。
- 管理员可以暂停或恢复整批、立即发起单笔、调整时间、撤销、处理未知结果，并导出 CSV。

## 状态

- `scheduled`：已保存，等待计划时间。
- `dispatching`：已被工作进程领取，正在调用钉钉。
- `retry`：明确的临时失败，等待自动重试。
- `unknown`：钉钉是否创建成功未知，禁止直接重发。
- `manual`：明确失败且不能自动恢复，需要管理员处理。
- `succeeded`：OA 已创建或已通过追踪号对账确认。
- `cancelled`：发起前由用户或管理员撤销。

## 配置与上线前置条件

配置示例见 `dingtalk.config.example.json`。功能默认 `enabled: false`。

正式启用前必须完成：

1. ECS Node.js 从 18 升级到 20/22（SQLite 驱动要求 Node 20+）。
2. 生成独立、长期不变并安全备份的 `encryptionKey`；密钥遗失会导致既有快照无法解密。
3. 确认 1—20 日入当月池、21—25 日直接发起、26 日至月底入下月池，以及管理员名单。
4. 若启用自动未知态对账，在所有涉及的 OA 模板中增加同名追踪号文本组件并填写组件名/ID。
5. 用测试账号完成一次跨天附件、发起人身份、主管审批和财务到达时间的真实链路验收。
6. 备份数据库并为 `data/` 设置磁盘容量和定期备份监控。
